# FACTS — the single source of truth for every guide

Every guide under `docs/guides/` states facts from this file and cites them by id (`T-…`). A fact lives here once. When a build changes a fact, update this row (statement, status, build, verified date) in the same commit as the ledger row; the guard (`node scripts/docs_guard.mjs`) refuses guides that cite an id that is not here, or that describe an unshipped fact as available.

**Status vocabulary.** `SHIPPED (build N)` is in a tagged build on TestFlight. `BUILT NOT SHIPPED` is on a pushed branch, not merged, no tag. `DEPLOYED (server)` is live in Cloud Functions or rules. `NOT BUILT`, `NEVER WORKED`, `NOT REACHABLE` (exists in code, nothing navigates to it), `NOT IN RELEASE` (debug builds only). `FACT` is verified against code, firmware or a measured result. `POLICY` is an owner decision. `UNVERIFIED` is stated by someone but not provable from the repo. Guides may describe only `SHIPPED`, `DEPLOYED`, `FACT` and `POLICY` rows as current; anything else is "coming" or left out.

**Sources.** `file:line` = code at the audited commit; `L:n` = `docs/BUILD_LEDGER.md` line; `D:n` = `docs/BUGS_AND_DEBT.md` line; `fw:n` = `esp32-bridge/src/main.cpp`; `owner YYYY-MM-DD` = owner decision. Audited commit: `c283d62` (app 2.5.10+116). Credentials, addresses, ids and customer identities never appear here.
